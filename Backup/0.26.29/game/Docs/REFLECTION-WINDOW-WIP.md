# Reflection window consumers (partial, unpublished)

Pinned reference: Ikemen GO cb56d73badb322f3725257c2e8cfd157b2c3989d, bytecode.go modifyReflection_window, char.go transient reflectWindow preparation and anim.go ReflectionList.add/draw.

ModifyReflection window now stores four caller-evaluated float32 components with the caller/recipient local-scale ratio. Fewer than four components warn without evaluating/writing them; more than four are explicitly rejected. All-zero custom windows inherit stage reflection.window. Root/Helper preparation resets the window to zero alongside other transient overrides.

The actual reflection draw queue receives a device-pixel clip rectangle. Unlike character sprite windows, native reflection windows are anchored to stage origin/ground, not actor position/facing or reflection offsets. Y is mirrored according to the sign of effective reflection Y scale, independently of its magnitude. Current live drawing is Training-only; its verified original localcoord is 1280x720 and WEB world width is 1280, so the stage-unit bridge is one before zoom/viewport fitting. Other stage coordinate systems are not claimed supported.

check-reflection-window.mjs first reproduces unsupported window (outputs/reflection-window-before.log), then covers redirected scaling, sequential samples, short arity warnings/no evaluation, reset isolation, stage fallback, reversed boundaries and positive/negative Y geometry. The old unsupported-window assertion now checks still-unsupported projection instead. Existing root/Helper fixtures use the extended default state shape.

Actual controller/draw fixtures check both root and normally spawned Helper clips, opposite player/facing directions, actor-motion independence, Y-sign mirroring and manually supplied stage fallback (outputs/reflection-window-consumers-browser.log). Stage reflection-window import, full native float32/pixel rounding/window composition/renderer behavior and other stages remain Pending; queued clip metadata is not proof of complete native raster equivalence.

Native ReflectionList.add rejects every reflection if stage intensity is zero, even with positive custom intensity. A separate actual failing-before gate reproduces the old bypass (outputs/reflection-stage-zero-before.log); the draw-list gate now matches this rule and the combined browser fixture passes (outputs/reflection-window-stage-zero-browser.log). Stage filter drawing remains outside that reflection-only gate.

Stage reflection.window now imports supported literal components as float32, retaining zero defaults for omitted trailing values. Python checks cover defaults, partial vectors, float32 rounding and explicit rejection of malformed/excess-component syntax. A failing-before parser check exposes the missing field (outputs/reflection-window-import-before.log). The existing production stage exporter already forwards parse_stage_reflection, so no extraction run or SFF/SND/image regeneration was needed. Training metadata now explicitly stores its unchanged zero window.

The real browser fixture now feeds Python parser output into the live stage reflection fallback, replacing its earlier manually supplied vector (outputs/reflection-window-import-browser.log). The later controlled queued-raster probe uses the actual reflection record's clip dimensions, translates the clip and synthetic opaque sprite together into an offscreen canvas, and proves inside RGBA [200,100,50,255] versus outside [0,0,0,0] (outputs/reflection-window-import-pixels-browser.log). This verifies clip consumption, not full native sprite/GPU/palette raster equivalence. Earlier stage-import Pending notes are superseded only for these supported literal cases.

Full stage parser syntax/localcoord systems, compiler/version/warning-prefix semantics, remaining reflection parameters/recipients/renderer behavior, combined regression and publication remain Pending. No whole-controller certification changes.
