# ModifyExplod cross-effect commit visibility — partial

Pinned reference: Ikemen GO cb56d73badb322f3725257c2e8cfd157b2c3989d, bytecode.go modifyExplod.Run, especially the final modifiers-outer/effects-inner loop, plus compiler_functions.go explodSub ordering. The previous consumer updated complete effects one at a time. That is observably wrong when a deferred window expression inspects another selected effect: the first window could see later effects' old priority and later windows could see earlier effects' new angles/ignorehitpause.

The production dispatcher now submits the selected collection to a real batch consumer. For currently supported parameters it completes all preceding scalar writes across the collection, evaluates/writes every window in selection/component order, then completes animation/geometry/ignorehitpause writes across the collection. Windows therefore see all preceding writes and none of the later writes, consistently across selected effects. Shared extraction remains once per controller, windows remain sequential/deferred per effect, and arrays are not aliased. Legacy extraction-only adapters can still collect scalar-only writes, but a window without the required batch consumer explicitly errors instead of silently performing a different order.

Independent checks verify phase ordering, exact cross-effect visibility, owner/value identity, separate window storage and missing batch-consumer diagnostics. Sixteen production root/normal-Helper/profile/player/character-version cases create two real common Explods with different old priority/angle values. The real CNS evaluator is instrumented only to snapshot live effects while evaluating actual window operands; evaluation still delegates to the original evaluator. Every one of eight component evaluations must see both new priorities but both original angles/ignorehitpause flags. Final real effects must then contain the new angles/flags. Evidence: outputs/modify-explod-batch-consumers-final.log. Existing drawing/resource/geometry matrices remain exercised.

This is a visibility-equivalent batch for the currently supported deferred expressions, not certification of every native modifier or engine phase.
