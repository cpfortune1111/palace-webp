# Controller value extraction (unpublished, partial)

Reference: Ikemen GO cb56d73badb322f3725257c2e8cfd157b2c3989d, src/bytecode.go BytecodeValue.ToF/ToB and BytecodeExp.evalF/evalB.

Native expression evaluation can retain Undefined, but a controller's evalF extraction maps Undefined and string values to float zero; evalB maps them to false. This conversion belongs at the parameter consumer, not inside the expression tree: changing arithmetic propagation would be incorrect.

Engine/controller-value-conversion.js now provides the float32/boolean extraction used by AngleSet/Add/Mul/Draw, AttackMulSet, DefenceMulSet and AttackDist. Float32 rounding, signed zero and infinities are retained; string values do not become numbers even when their text is numeric. DefenceMulSet still applies its reciprocal/direct policy after extraction, so legacy reciprocal zero can legitimately become infinity.

Tools/check-controller-value-conversion.mjs covers explicit undefined/NaN, numeric and nonnumeric strings, booleans, infinities, float rounding and signed zero through production modules. Eight actual browser actor scenarios feed 1/0 and Name through the real parser and controller dispatcher, observing zero angle axes, attack multipliers, direct defense multiplier and guard-distance components, with false onhit. Evidence: conversions assertions in Tools/check-debug-clipboard-browser.cjs and outputs/controller-conversion-browser.log.

The extraction path also covers PosSet/PosAdd and VelSet/VelAdd/VelMul float operands, plus HitVelSet boolean axis enables. Pinned posSet/posAdd/velSet/velAdd Run methods sample evalF before float32 redirected scaling; hitVelSet.Run explicitly uses evalB. The redirected ratio is now rounded before multiplication. Failing-before tests show undefined HitVelSet previously enabled a hit velocity of 100 instead of retaining 8. The expanded module gate verifies disabled invalid hit axes, zero invalid velocity operands, PosAdd retention and PosSet camera/ground origins. Existing position/velocity module gates pass. These newer movement edge cases have module evidence only until an actual-browser case is added.

Subsequent actual-browser movement evidence uses findMovementActor live bindings, not root snapshots. Eight profile/player/root-or-Helper scenarios dispatch HitVelSet/VelAdd/VelMul/VelSet and PosAdd/PosSet through the common controller path with parsed 1/0 and Name operands. Invalid HitVelSet preserves velocity 8/9; VelAdd preserves it, VelMul and VelSet yield zero, PosAdd preserves both coordinates, and PosSet produces finite camera/ground-relative coordinates with zero depth. These assertions exercise the production coordinate wrappers and real actor storage. Evidence: movement assertions in Tools/check-debug-clipboard-browser.cjs and outputs/movement-conversion-browser.log.

Only these consumers have this new extraction path. Other controller parameters, integer conversions, full type tags, legacy executable differential behavior and complete VM/version/scheduling semantics remain Pending. No complete-controller certification is claimed. Final regression and publication are separate gates.

The common controllerTriggered consumer now applies controllerBoolean to triggerall and grouped triggers, matching pinned BytecodeValue.ToB rather than JavaScript nonempty-string truth. A Map string such as "3" is false as a trigger even though it remains a string when read as a value. Undefined and zero remain false; nonzero numeric values retain truth. OR between trigger groups and AND within each group are unchanged.

Tools/check-controller-trigger-coercion.mjs first observed text incorrectly activating the real extracted trigger function. Eight actual actor cases then dispatch VarAdd with Map string/undefined/missing/numeric triggers and observe counter history [0,0,1,1,1], including an alternate successful numeric group. Evidence: triggerResult assertions in Tools/check-debug-clipboard-browser.cjs and outputs/trigger-coercion-browser.log. Full trigger compilation, native short-circuit phases and other boolean parameter consumers remain Pending.

EnvShake float fields phase/freq/mul/dir/diradd/decay now use controllerFloat32, matching pinned envShake.Run. Its time/ampl extraction also avoids interpreting string text as a number, while existing integer conversion/range boundaries remain separately uncertified. Explicit Undefined phase now becomes 0 rather than being confused with the omitted-phase sentinel, which would select 90 when frequency is 90. Existing compiler order, clear/replacement behavior, clamps and native amplitude scaling remain unchanged.

Tools/check-env-shake-controller.mjs first observed phase 90 instead of 0; invalid float-field and string time/amplitude cases now pass. Eight actual actor cases dispatch EnvShake with parsed 1/0 and Name, observing zero phase/mul/direction/decay fields, frequency 90 and finite amplitude, then restore the prior shake. Evidence: shakeResult assertions in Tools/check-debug-clipboard-browser.cjs and outputs/envshake-conversion-browser.log. Complete native integer overflow, shake rendering/version/scheduler and all parameter certification remain Pending.

ScoreAdd and TargetScoreAdd now also use controllerFloat32, matching the pinned scoreAdd.Run / targetScoreAdd.Run evalF consumers. Their old Number conversion accepted numeric strings and allowed Undefined NaN into the shared score accumulator. Tools/check-target-score.mjs first observed a baseline score of 5 becoming NaN; undefined/string cases now preserve both round and total scores. Existing float32 accumulation, filtering and NoScore cases remain intact.

Eight actual actor cases seed a finite fractional score, register the opposing root as a target, then dispatch both score controllers with parsed 1/0 and Name. Both player score entries remain finite and equal to their pre-call values. Evidence: scoreResult assertions in Tools/check-debug-clipboard-browser.cjs and outputs/score-conversion-browser.log. Complete score ownership/version/phase semantics and native executable parity remain Pending; no certification count changes.

StateDef velset now also extracts each supplied XYZ component through controllerFloat32, matching bytecode.go stateDef.Run's sequential evalF writes while retaining omitted axes. Tools/check-state-def-velocity.mjs first observed NaN instead of zero and now covers undefined and string operands without altering existing sequential-write/default checks. Eight actual browser scenarios spawn a Helper from root/Helper callers on both player slots/profiles into a definition with velset=[1/0,Name,1/0]; all three stored velocities are finite zero after real state entry. Evidence: stateVelocity assertions in Tools/check-debug-clipboard-browser.cjs and outputs/state-velocity-conversion-browser.log. Complete root/native-entry/version scheduling remains separately bounded.

TargetVelSet/TargetVelAdd now use the same float extraction, matching their pinned Run methods before redirected scaling and target selection. Sampling order, axis omission and the pinned cumulative multi-target scaling behavior are retained. Failing-before module tests observed NaN replacing a target velocity of 12; the corrected tests cover undefined and string values for both add/set. Eight actual actor cases register a real opposing root target, send Name and 1/0 through dispatcher expressions, observe TargetVelAdd preserving 8/9 and TargetVelSet writing 0/0, then restore the target list. Evidence: Tools/check-target-velocity.mjs, targetMovement assertions in Tools/check-debug-clipboard-browser.cjs, outputs/target-conversion-browser.log. The in-flight complete regression began before this target-only conversion change and cannot certify it by itself.
