# Gravity controller consumer (partial, unpublished)

Pinned reference: Ikemen GO cb56d73badb322f3725257c2e8cfd157b2c3989d, bytecode.go gravity.Run/getRedirectedChar and char.go Char.gravity. Native Gravity applies to the selected Character without a standing/airborne/control-state gate. It adds the recipient's own movement.yaccel multiplied by its own-coordinate/current-state-coordinate scale ratio, with float32 accumulation. This is distinct from automatic aerial physics gravity and does not replace it.

WEB Gravity previously fell through to unsupported controller dispatch. The real browser failing-before fixture records M2 unsupported controller: Gravity (outputs/gravity-controller-before.log). A new shared controller now resolves optional redirectid with native integer extraction, rejects missing recipients before reading constants, and adds recipient-local Y velocity using the existing native-to-world binding. Its own acceleration comes from the recipient's originalMotionConstants, not the caller's expression scope or foreign state provider. Unknown payload parameters fail explicitly; common persistence/hitpause metadata remains owned by the shared scheduler.

check-gravity-controller.mjs verifies omitted/redirected execution, isolated caller velocity, different Helper acceleration/coordinate scales, signed ID wrapping, string/undefined/NaN IDs, missing-recipient early return, float32 operation order and explicit unsupported fields. Actual root dispatch in both directions sets different owner constants and confirms only the recipient's world velocity changes (outputs/gravity-controller-root-browser.log).

The actual custom-state fixture initially failed for a root in foreign state ownership: observed world velocity 4.625 instead of independently expected 4.125 (outputs/gravity-coordinate-consumers-browser.log). The new adapter had incorrectly reused collisionActorData, whose profile follows custom state ownership. Gravity now explicitly selects own-character data for acceleration and own scale; current-state scale remains distinct. Other collision consumers were not globally changed.

Sixteen actual profile/player/root-or-normal-spawn-Helper/own-or-foreign-state cases now pass with deliberately different 320/640 localcoords and recipient constants (outputs/gravity-coordinate-consumers-fixed-browser.log). Both omitted and explicit redirect execution match the independent staged float32 world-velocity calculation while other roots remain unchanged. Profile, entity registry, coordinate arrays, acceleration constants, state ownership, velocities and fixture state definitions are restored in finally.

Sixteen additional actual scheduling cases pass across both named profiles and player directions: root current/global calls, lifecycle global-state dispatch and normally spawned Helper current/global execution during local hitpause (outputs/gravity-scheduling-browser.log). CNS literal flags 1 + 0 and -2 execute; 0.5 does not. This proves these scheduler adapters consume Gravity, not full native pause/persistence/lifecycle equivalence.

Remaining native coordinate/version/compiler diagnostics, complete persistence/global-pause/lifecycle fidelity and final regression/publication remain Pending. No whole-controller certification changes.
