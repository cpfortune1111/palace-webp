# HitDef state changes — partial common prerequisite for ReversalDef

Reference: Ikemen GO `cb56d73badb322f3725257c2e8cfd157b2c3989d`, `src/bytecode.go` hitDef_p1stateno/p2stateno/p2getp1state cases and `src/char.go` hitResultCheck.

The shared compiler evaluates P1/P2 state numbers once as int32 and P2GetP1State once as a boolean. Writing P2StateNo implicitly enables source-state ownership before an explicit P2GetP1State override, including when the supplied state number is negative. Focused tests cover expression order, overflow and explicit own-state selection.

The live root contact resolver now honors this ownership flag, records its GetHit metadata and excludes negative state numbers from explicit target-state entry. An explicit ownership flag can also select the source's ordinary get-hit state table without a P2StateNo. KeepState does not replace current ownership, and the old paired throw shortcut no longer accepts negative state numbers or KeepState. Its remaining nonnative shortcut semantics still require replacement.

Explicit root P2StateNo enters the selected state table and forces MoveType H/control false even if the target StateDef is an idle/locomotion state. P1 recipient execution can use the ordinary state driver when the destination is not a reaction state instead of sending every destination through the reaction-only driver. A current runtime fixture covers actual P2 locomotion-state entry; broader P1/source-owner cases are still required.

The first full compilation/ownership regression ended with exit 0 (`outputs/controller-hit-state-ownership-browser.log`). The next complete regression also passed (`outputs/controller-hit-state-ownership-execution-browser.log`), including explicit own/source metadata, own negative-state exclusion, source ownership without P2StateNo, KeepState preservation and actual target-state execution.

Generic P1StateNo execution now has root and Helper source hooks after accepted-contact bookkeeping. Guard and HitOverride do not trigger source changes; recipient KeepState does not suppress them. Projectile sources select their original root/Helper owner for state entry. Source control is cleared after entering its own state. A real spawned Helper collision enters its own state 20 through this hook, while a live root adapter fixture distinguishes guard/override rejection and KeepState acceptance. The new full regression is tracked separately; projectile-owner and complete P1 accepted-contact trajectories need additional evidence.

The complete generic source-state regression passed with exit 0 (`outputs/controller-hit-source-state-browser.log`). Further fixtures now exercise both real root accepted-hit callbacks with standalone P1StateNo, and the projectile adapter with live Helper/root owners. The paired legacy path also clears source control after StateDef entry and forces recipient H/control false instead of letting an idle StateDef restore control. Its combined standalone/paired root fixture result is tracked separately; the paired path still does not have full native damage/effect semantics.

Definition compilation now snapshots the state-provider table and whether it is foreign from the original actor context. Recipient/source state entry consumes that captured provider rather than the actor's later character/body table. A registered alternate table contains a state absent from the body table; actual target and source execution both reach that state after the source leaves the alternate provider. Existing same-character P2 source-state tests retain their foreign-state distinction rather than normalizing an equal character name to own state. An additional fixture checks source snapshots for that same-character distinction and normal Helper independence.
