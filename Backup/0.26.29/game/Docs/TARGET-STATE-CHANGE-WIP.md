P2StateNo selects the incoming state, forces MoveType H and clears control before its header executes. The incoming header must not assign animation, physical type, velocity, power or control during hitpause. StateDef initialization may subsequently replace the forced H/control values. TargetState has a separate control-clear phase and does not itself force H; its root WEB consumer now also selects through the real pending-state buffer.

The root custom-hit consumer now uses the existing real pending-state buffer for both recipient slots. It retains the prior animation/velocity, carries the new GetHit data and defender pause, and initializes the selected header after the recipient becomes eligible. The reversal target consumer currently shares this entry function; complete reversal/native action ordering remains unverified.

Tools/check-target-state-change.cjs reproduces eager initialization before the patch and observes both actual root consumers after it: two own-hitpause actions retain old fields, the later header consumes IgnoreHitPause VarAdd output, and the first normal body observes Time=0. It additionally executes actual TargetState controllers through each root slot with live hit-ID-selected targets; the non-H move type survives selection, distinguishing TargetState from P2StateNo. The valid red controller run fails on eager header fields; the green run passes all twelve profile/controller/contact cases. Original Moon throws also complete in both root slots against Venus.
