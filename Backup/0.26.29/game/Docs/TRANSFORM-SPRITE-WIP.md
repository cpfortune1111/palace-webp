# TransformSprite window consumers (partial, unpublished)

An actual 27-case redirected-coordinate fixture exposed and fixed a real adapter error: TransformSprite localscl must use native 320 / actor localcoord, not WEB world width / localcoord. Unequal WEB rendering widths incorrectly doubled recipient values even though the native coordinate ratio was unchanged. The adapter now reuses collisionLocalCoord, including explicit Helper localCoord. Cases cover all root/Helper caller-recipient pairings at 320/1280, 1280/320 and 640/640 root widths, a 640 Helper width and unequal 1280/640 WEB widths. Before-fix failure: outputs/transform-native-coordinates-before.log. This closes the tested native-versus-rendering-scale distinction, not complete borrowed-state/provider/phase fidelity.

The synchronized controller/effect chain now also copies xshear. Actual TransformSprite writes -0.25 to P2 and +0.5 to a Helper; their ordinary synchronized Explods retain those scalar values and real draw matrices. After syncparams is disabled, clearing both targets' window/shear fields does not alter the retained clips/matrices. Explicitly zeroing the effect shears changes both real draw matrices, confirming a drawing consumer rather than metadata-only propagation. Native perspective/custom-owner/phase fidelity remains Pending.

TransformSprite xshear is now supported on the tested affine paths, superseding its earlier explicit rejection. It evaluates after window in caller scope and writes the redirected recipient without coordinate multiplication. P1/P2 have independent transient shear storage; Helper entities retain their own field. Real body drawing applies native-style unrotated/rotated shear before scale/rotation around the character axis, including signed Helper/AngleDraw scale in compensation. Twelve actual browser cases redirect positive/negative shear to both roots and a Helper, with rotations 0/90, and verify live storage plus all linear draw coefficients. Root/Helper preparation clears transient shear alongside window. Focallength/projection still fail explicitly, and full offset/reflection/phase/coordinate/GPU equivalence remains Pending.

The actual browser root reset adapter now has corresponding phase cases for both P1/P2: local hitpause clears transient windows, blocking global Pause with zero move allowance retains them, and resumption clears them. Real specialRuntime pause/movetime slots are used and restored. Combined with Helper runtime fixtures this establishes the selected supported reset boundaries; full negative/global/body scheduling and SuperPause allowance combinations still require coverage.

Real Helper runtime/reset evidence now covers both engine profiles, both player slots and both facings. A Helper CNS TransformSprite writes its window on the first active frame; disabling its controller clears that transient window on the next preparation. Local hitpause still clears the window, while a blocking global pause retains it and its hitpause clock until unpaused. This matches the pinned actionPrepare reset being inside !pauseBool but outside the !hitPause width/reset subsection. The executable fixture uses createSpecialRuntime and actual generic Helper controller dispatch, not a direct reset callback. Full negative-state/pausemovetime/rollback phase equivalence remains Pending.

The complete supported window chain now has actual consumer coverage: TransformSprite redirects to P2 and a live Helper, writes independent native-style window vectors, positive syncId copies each window into its ordinary Explod, and real effect drawing produces nonempty clips. Disabling syncparams before clearing both target windows retains the prior effect vectors and clip dimensions. Value-copy semantics prevent later target mutation from changing retained windows. This follows pinned Explod synchronization's e.window = syncChar.window; full cross-owner coordinate and native phase equivalence remain Pending.
