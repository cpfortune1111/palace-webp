# ModifySnd — partial unpublished implementation

Current status: every parameter in the pinned ModifySnd inventory has a runtime path, but this is not full semantic certification. Forty actual root waveform cases pass, plus six normal-Helper ownership/redirect cases. Full scheduling, mid-stream browser buffer/clock behavior, version/compiler diagnostics, extreme float32 arithmetic and final regression/publication remain required. Earlier unsupported statements below are historical development notes.

Reference: Ikemen GO cb56d73badb322f3725257c2e8cfd157b2c3989d, compiler_functions.go modifySnd and bytecode.go modifySnd.Run.

The shared root/Helper dispatcher now accepts recipient redirection, optional channel (-1 selects only that recipient's owned channels), relative/absolute pan, native ModifySnd volume/volumescale arithmetic, priority and hit/state stop flags. Omitted fields retain existing values. Unlike PlaySnd, volumescale uses recipient data.volume even for common sounds. Volume updates use a separate output gain setter so they do not reset pan state. Missing recipients skip payload evaluation. Independent extraction tests pass, including ordered pan/abspan and volume/volumescale overrides.

Eight actual root-controller cases now modify already attached native voices for both players and own/common sounds. Independent 64-frame stereo expectations cover volume=-128 and volumescale=25, preserve existing nonzero absolute pan, and verify priority and stop flags. The complete actor browser suite passes (outputs/modify-sound-volume-waveform-browser.log, exit 0). These apply controls before offline rendering starts; they do not establish mid-quantum timing or device latency.

Frequency mutation now reaches a native-player control message and the production worklet calls phase-preserving resampler SetRatio semantics. Independent stream tests change speed after consuming samples and check continuity; processor tests change an infinite stream between quanta without resetting it. The player copies its parameter descriptor, forwards updates to attached nodes and rejects updates after release. Real browser ModifySnd frequency waveform/latency consumers are still required; unit/worklet-model results alone do not establish complete fidelity.

Eight actual P1/P2 own/common frequency cases now cover updates before readiness and after native-node attachment. The first post-attachment render failed because sending a MessagePort command does not prove the audio thread has applied it (outputs/modify-sound-frequency-waveform-browser.log). Numbered modification acknowledgements now expose the applied source-output frame; pending acknowledgements resolve on cancellation. Tests await actual acknowledgement before offline rendering, not an arbitrary sleep, and exact source-step samples pass (outputs/modify-sound-frequency-ack-browser.log, complete actor suite exit 0). This establishes acknowledged output and exposes asynchronous delivery; it does not make the synchronous game controller block or certify native speaker-lock/device latency parity.

Position mutation now uses native-wide integer extraction and changes only the underlying source cursor. It deliberately does not reset the resampler's already-buffered 512-frame block, matching the pinned snd.streamer.Seek call. Independent stream and production-processor tests consume samples first, seek to 1000, verify the old buffered tail, then observe samples starting at 1000. Pending-loader updates initialize the source position without mutating the caller descriptor. Actual browser position-consumer coverage remains required.

Loop mutations remain explicitly unsupported and throw rather than being ignored. This controller is not complete or certified. Redirected/normal-Helper ModifySnd consumers, full native float32/compiler/version semantics and complete scheduling/regression remain required.

Sixteen actual frequency/position cases now pass for both player directions, own/common resources and updates before/after native readiness (outputs/modify-sound-position-waveform-browser.log, complete actor suite exit 0). The position cases acknowledge seek before the first rendered quantum; the previously buffered mid-playback tail remains covered by the separate production-processor model, not this browser consumer.

Dynamic-loop groundwork adds mutable loop points and remaining-repeat count to the source looper, preserving its current cursor and native chunk-sensitive finite tail. Standalone tests cover changing points while active and disabling loops. These setters are not yet controller/worklet consumers. A nonadvancing infinite range explicitly errors instead of reproducing the native infinite hang; this malformed-range edge remains uncertified.

Subsequent implementation connects loop/loopcount/loopstart/loopend through the controller, player update queue and worklet to the mutable source looper. loopcount overrides loop and converts play count to remaining repeats. Source tests preserve the pinned SetLoopPoints behavior: a changed single endpoint passes zero for the unspecified endpoint, whereas an unchanged endpoint does not reset the other. Loaded-source updates do not clear resampler buffers. Pending updates now replay in order after source construction, fixing valid-seek followed by invalid-seek incorrectly collapsing to an invalid initial position. Independent controller/stream/player/processor tests pass. Actual browser loop consumers, full parameter/default/version/compiler fidelity and regression remain required; earlier unsupported statements describe the previous implementation stage.

Sixteen actual root loop-modification cases now pass across both players, own/common resources, pending/attached voices and finite/infinite loops. They compare every stereo sample against an independent source-window sequence, show loopcount=2 overrides loop=1, verify finite completion removes the record and StopSnd clears infinite player/mixer resources (outputs/modify-sound-loop-waveform-browser.log, complete actor suite exit 0). These modifications are acknowledged before offline rendering begins; mid-stream buffered loop changes, redirected/normal-Helper consumers and complete native timing/compiler/version fidelity remain separate requirements.

Six actual redirected normal-Helper cases now verify default channel=-1 selects only the recipient's owned channels, not all players and not a second application of playback inheritance. Parent/root-inherited voices stay untouched, independent Helper voices receive absolute-pan/priority/stop updates, and opposing voices retain their state. Helpers and nested parents are normally spawned, with native instance IDs (outputs/modify-sound-helper-ownership-browser.log, complete actor suite exit 0). This is actual channel/graph-state ownership coverage, not redirected Helper waveform or normal-state scheduling certification.

Forty actual ModifySnd scheduling groups now pass through root current/global/lifecycle and normal-Helper current/global execution in both runtime profiles and player directions. They check literal hitpause gates, current/global persistent=0 differences and Helper global-pause movement allowance by observing real pan-graph changes. The combined SndPan/ModifySnd matrix has 80 groups (outputs/modify-sound-actual-scheduling.log, exit 0). This supersedes the earlier missing normal-state scheduling note, but not full compiler/version/timing certification. Worklet, native stream and mutable-loop module URLs now have release-02583 cache identities so existing clients do not retain incompatible processors.
