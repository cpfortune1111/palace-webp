# Sprite window consumers (partial, unpublished)

Screen-space evidence now includes 48 actual Root/Helper left/right postype cases with camera zoom 0.5/2 and all horizontal/vertical reflection signs. The ordinary spawn/draw path produces independent viewport-anchored clip rectangles and matrix signs; stage zoom does not alter screen window sizes or offsets. The fixture also uses nonunit sprite scale 3,4. Native postype conversion/binding and explicit space/redirect/custom-owner coordinate semantics remain Pending: these cases validate the currently supported left/right draw paths rather than certifying all screen positioning rules.

Ordinary angle/xangle/yangle now evaluate into real effect rotation storage with pinned compiler-relative order angle, yangle, xangle and float32 operands. Thirty-six actual P1/P2/Helper draw cases cover Z=90, X=60 and Y=60 under all four horizontal/vertical reflection combinations. Independent expected linear matrices verify rotation, orthographic foreshortening and odd-reflection corrections; stored angles remain unchanged by drawing. This is orthographic consumer coverage, not full native perspective/projection/interpolation/GPU equivalence or complete cross-parameter compiler ordering.

Ordinary Explod facing now retains the native distinction between base facing and the controller's relative sign. The integer facing operand is evaluated once and combined only for drawing/window orientation, so sprite mirroring does not rewrite movement or the synchronized base facing. The round-effect fallback no longer evaluates facing twice or treats its relative operand as an absolute direction. Screen sprites now also retain the resolved drawing-facing sign. Actual actor coverage expands to 96 cases across owner facing, relative facing, VFACING, two coordinate widths and two scales, asserting both draw-matrix signs and independent clip rectangles. Native postype binding/velocity/screen/round-resource and synchronized relative-facing combinations still need additional verification.

VFACING now has ordinary Explod storage and draw consumers. Its integer operand selects -1 only for negative extracted values; absence/zero/invalid runtime strings select +1. Vertical sprite scale and the window's base Y scale both apply this sign. Ordinary effect rotations use the native odd-reflection correction: when horizontal and vertical facing signs differ, Z and Y angles are negated without mutating stored angles; X angle is retained. The actor window fixture now covers 48 cases with both vertical signs and verifies actual vertical draw-matrix signs plus clipped Y offsets. Node tests cover all four reflection combinations. Combined rotated/perspective/vfacing pixel equivalence and full compiler ordering remain Pending.

Actual creation/draw coverage now includes 24 P1/P2/Helper cases: both facing directions, 320 and 1280 local-coordinate widths and effect scales 1,1 versus 3,4. Real profile coordinate systems are temporarily selected, spawnSourceExplod evaluates the four window components and drawSourceExplods produces the rectangle. Independent expected viewport/camera/truncated rectangles verify facing offsets and base coordinate ratios; changing effect scale does not resize the window. Profile objects/effects are restored after the fixture. This closes the ordinary owned stage-space coordinate evidence gap, not redirected/borrowed-provider/vfacing/depth/screen behavior.

A zero four-vector disables the window; reversed corners are sorted. Window scale uses base scale/facing, not the effect scale or rotation. Screen rectangles truncate origin and size independently to native integer coordinates.

Ordinary WEB Explod creation now evaluates a four-component float32 window. Short vectors warn without evaluating components; oversized vectors fail explicitly. Drawing computes a camera/viewport/local-coordinate/facing rectangle, retaining it separately from the sprite transform. The draw queue snapshots the rectangle and clips during rasterization; immediate sprite drawing applies the same absolute clip. Zero-sized nonzero windows clip everything, rather than disabling clipping.

Focused tests cover operand order, invalid runtime strings, zero sentinel, reversed/facing-scaled corners, integer truncation and zero width. An actual browser pixel fixture verifies both immediate and resolved rendering: only the middle pixel of a translated three-pixel white source survives an absolute one-pixel window. Mutating the caller rectangle after recording does not widen the queued clip.

Actual Root/Helper Explod window metadata/coordinate tests, redirected owner local-coordinate scaling, screen/vfacing/depth/custom-state cases, synchronized target windows, full compiler order/diagnostics and native integer overflow/GPU scissor equivalence remain Pending. This is not whole window/Explod certification.
