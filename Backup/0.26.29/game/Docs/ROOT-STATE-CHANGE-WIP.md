# Root selected-state initialization — 0.25.37 partial implementation

Pinned reference: Ikemen GO cb56d73badb322f3725257c2e8cfd157b2c3989d, char.go stateChange1/stateChange2, actionRun, tick and hitResultCheck; bytecode.go newStateBytecode/StateBytecode.init. This checkpoint does not certify whole controllers or the complete native scheduler.

P1StateNo sources now use real selection/header buffering for P1 and P2 roots, including a P1 source represented by an existing reaction actor. StateNo, PrevStateNo and Time are selected immediately and control is cleared; physical types, animation/age, priority, velocity, cost and power remain live until initialization. The request remembers its source provider. Reaction-origin P1 selection preserves the existing GetHit object and exposes its hit-time clock while pending; an IgnoreHitPause GetHitVarSet updates that pending clock rather than an absent reaction object.

The root action paths initialize an eligible later request after existing globals, not during its selection tick or its own/global pause. Pending current-state IgnoreHitPause controllers still execute once through the normal controller scheduler. P2 can resume after its own clocks end while P1 remains paused, and its source attack clock advances after that first body. Normal entry replaces/cancels queued work; round reset and character preparation discard pending requests. Result/presentation paths consume pending headers and their pause clocks too, so a last-hit request is not held forever merely because combat has ended.

Source headers retain explicit U and animation -1 values, execute a real Time=0 body and perform the intrinsic non-attacking juggle reset before provided fields. Engine/state-def-types.js distinguishes omitted intrinsic fields (native S/I/N defaults) from explicit U retention; it is used by the root/reaction and Helper header adapters. Existing legacy entry/presentation shims are not thereby certified.
