# ModifyReflection real consumers (partial, unpublished)

Helper recipient/drawing support now supersedes earlier blanket Helper unsupported notes for the already supported color/intensity/offset/scales/orthographic-angle operands only. Real normal-spawn Helper fixtures cover alpha, geometry, color, preparation resets and visibility gates; unsupported animation/window/shear/projection fields still fail explicitly. See HELPER-REFLECTION-WIP.md and NO-SHADOW-WIP.md. No complete controller certification is implied.

Reference: Ikemen GO cb56d73badb322f3725257c2e8cfd157b2c3989d, compiler_functions.go modifyReflection, bytecode.go modifyReflection.Run, char.go preparation/reflection sprite creation and anim.go ReflectionList.draw.

Supported root-character operands now reach real reflection drawing: redirectid, intensity, offset, xscale and yscale. Recipient lookup precedes caller-scoped RHS sampling. Intensity uses native signed integer extraction and clamp 0..255; offsets use sequential float32 writes and caller/recipient localscl ratio; scalar scales do not use that ratio. A short offset retains its omitted component. Override scale zero means inherit stage scale, not collapse the reflection.

Root preparation resets overrides to native transient defaults: intensity -1, offset [0,0], scales zero. Character preparation also clears them. The existing root pause/preparation gate controls reset timing; complete native pause/version lifecycle verification remains Pending.

Actual redirected P2-to-P1 controller execution changes recorded reflection alpha, horizontal/vertical matrices and screen displacement while leaving P2 unchanged. Tests hide the reflection at zero intensity, restore inherited stage scaling with zero override scales, and reset transient fields through the actual preparation helper (outputs/modify-reflection-actual-browser.log). Independent tests cover defaults, operand order, missing targets, unsupported fields, scalar extraction, redirected coordinate ratio and omitted offset components. Baseline actual actor fixtures still pass.

This is not a complete controller implementation. Unsupported parameters fail explicitly instead of being retained as inert metadata. Helper/projectile recipients also fail explicitly until their reflection rendering exists. Other stages, color, keeptransform, window, shear, rotations, animation/resource providers, projection/focal length, exact native window/depth/size/palette/GPU behavior, full lifecycle/diagnostics and final combined/versioned publication gates remain Pending.

Delegated x/y/z parameters have an additional pinned-reference discrepancy: compiler_functions.go calls posSetSub, whose IDs overlap this controller's animation/provider IDs. Static evidence is retained locally in outputs/modify-reflection-reference-review.json; native executable reproduction or official reference resolution is still required. Ordinary position semantics must not be invented or counted as implemented. No whole-controller certification changes.

Coverage now includes both recipient directions, not only P2-to-P1 (outputs/modify-reflection-both-roots-browser.log). Both roots clear override state during local hitpause, retain it while a global pause blocks their preparation, and clear it when preparation resumes (outputs/modify-reflection-phase-browser.log). These exercise the actual root preparation helper; exhaustive native phase/version combinations remain Pending.

The local parameter validator accepts ignorehitpause/persistent because their execution belongs to the existing shared CNS scheduler, not this drawing module. Empty controllers avoid unnecessary recipient storage access, preserving the native no-change case even for an otherwise unsupported Helper target. This does not implement Helper reflection drawing or certify scheduler semantics for the whole controller. Fresh combined/versioned gates remain required after these validator cases were added.

keeptransform, angle, xangle and yangle now also reach real orthographic root drawing. Operand order matches the pinned compiler: keeptransform follows intensity; angles follow scales. Native rotation composition adds custom nonzero angles or stage fallback to the active source rotation, with the pinned negative-source Z/Y correction. The Canvas adapter converts native facing-adjusted Z/Y back to its mirrored coordinate convention. keeptransform=false uses custom rotation without source/stage rotation but preserves source scale/pivot data; it is not a blanket scale reset.

Independent cases cover both facings, negative source angles, stage fallback, keeptransform=false and evaluation order. Eight actual matrix cases (four per root recipient) compare real controller output with independently constructed affine reference matrices, including scale/pivot retention (outputs/modify-reflection-angle-browser.log). Stage fallback is supplied as runtime fixture data; importing nonzero stage angle settings remains a separate Pending path. Full perspective/projection/size/pivot/palette/GPU/native phase equivalence and remaining controller parameters/recipients are still Pending. Earlier unsupported-rotation notes are superseded only for these real consumers.

The nonzero stage-angle import gap is now covered for supported numeric literals. stage_reflection.py returns angle/xangle/yangle with native zero defaults and float32 storage, and the existing stage exporter already forwards its returned object. Training's current DEF omits these settings, so its runtime JSON now makes the three zero defaults explicit without regenerating imagery. The actual browser fixture invokes the production Python parser and feeds its JSON result into the real stage reflection renderer; both roots' fallback matrices pass (outputs/modify-reflection-import-angle-browser.log). Python tests cover omitted settings, signed angles and float32 fractional storage. The original SFF/SND and full image exporter were not run or uploaded. Complete native stage parsing/version/nonfinite behavior remains Pending; the earlier nonzero-import Pending note is superseded only for these tested literal cases.

color now reaches real root reflection shader output. Components use native staged integer reads, clamp 0..255, and zero omitted RGB components; the whole vector commits before intensity/remaining operands. Default [-1,-1,-1] inherits stage color, whose native default is white. The renderer multiplies the sampled actor PalFX multipliers by RGB/255 using float32 multiplication and integer truncation, then applies existing AllPalFX composition. It does not mutate the actor's sampled effect. This also closes the earlier missing actor-PalFX propagation in reflection records.

Both root recipients have actual controller-to-record-to-shader/compositor pixel probes for white, red and black; combined own/global effects produce [53,15,0,255] on the controlled RGBA input. Tests verify own palette arrays remain unchanged and the other root receives only the global effect. Production parser output supplies a red stage fallback and matches the explicit controller tint (outputs/modify-reflection-color-import-browser.log). The pixel probe isolates color at a known RGBA sample; it is not a claim of full GPU/geometry equivalence. Native RGB defaults/clamps and short vectors have Python checks, and Training now declares its unchanged white default without image regeneration. Updated color-specific pause/reset assertions and fresh combined/versioned gates remain required. Earlier unsupported-color notes are superseded only for these real root consumers.
