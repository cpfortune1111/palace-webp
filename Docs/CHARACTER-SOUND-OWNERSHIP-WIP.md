# Character sound ownership — partial implementation

Reference: Ikemen GO commit `cb56d73badb322f3725257c2e8cfd157b2c3989d`, `src/char.go` (`getOwnChannels`, `playSound`), `src/bytecode.go` (`StopSnd.Run`) and compiler StopSnd channel validation. Cached reference files are not release assets.

The WEB registry tracks sounds by actual root/Helper identity and logical channel, rather than treating P1/P2 channel offsets as ownership. Automatic negative channels overlap. Replacing a numbered channel affects only the same owner. End/error/rejected playback releases the matching record without removing a replacement. Round reset stops registered character audio.

Helper `inheritchannels` is extracted as a native integer at creation. Playback allocates to the immediate parent for 1, the root for 2, otherwise the Helper itself. This is not recursive parent inheritance. StopSnd selects actual recipient ownership and does not repeat playback inheritance. Channel -1 stops all character sounds; other negative channels select all sounds belonging to the recipient. Missing redirected recipients skip channel evaluation.

Tests: `Tools/check-character-sound-channels.mjs` covers identity, ownership, nonrecursive inheritance, high numbered channels, replacement, automatic overlap, redirected stop, negative selection and cleanup. `Tools/check-sound-reference.mjs` covers native integer extraction of evaluated group/item values, including strings, undefined, NaN and int32 wrapping. All 233 Node checks pass in `outputs/sound-ownership-node.log`.

Actual actor wiring previously reproduced StopSnd redirecting to P2 but stopping P1 (`outputs/stop-snd-owner-before-corrected.log`). The corrected controlled-media fixture passes (`outputs/stop-snd-owner-browser.log`). This is wiring evidence, not audible playback or stereo-output proof.

Native `Char.playSound` rejects negative group numbers. An actual shared PlaySnd fixture reproduced an unwanted media allocation for a negative common group before the guard (`outputs/negative-sound-group-before.log`). Both negative own and common group paths now allocate no media (`outputs/negative-sound-group-browser.log`). Channel expression extraction remains before this playback guard, matching the distinction between controller evaluation and sound allocation.

Six actual normally spawned nested-Helper cases now cover both player directions and inheritance 0/1/2. PlaySnd allocates the expected recipient-owned resource and channel; stopping the child, then parent, then root proves allocation ownership is not inherited recursively or reapplied by StopSnd (`outputs/helper-sound-ownership-browser.log`). Fake media elements exercise the production dispatch/registry path, not decoded sound output. The older `check-specials.cjs` test timed out waiting for its LOGO startup path before reaching its audio assertions (`outputs/sound-ownership-specials.log`); this is not a passing full regression gate.

Numbered-channel replacement now honors `priority` and `lowpriority`, extracted from caller expressions with native integer/boolean rules. An active same-owner channel rejects low-priority requests or requests below its stored priority; equal priority replaces it. Automatic channels retain native zero stored priority. Both own/common PlaySnd paths forward these options. Independent rejection/replacement tests and the existing actual actor suite pass (`outputs/sound-priority-actor-browser.log`). Reference: pinned `src/sound.go`, `SoundChannels.Request` and `SetPriority`. Capacity exhaustion, configured channel normalization and oldest-channel eviction are not implemented by this partial replacement policy, and additional actual priority-expression fixtures remain required.

Four additional actual own/common PlaySnd fixtures cover both players: lower priority and `lowpriority=1` preserve the active sound, equal priority replaces it, quoted numeric priority extracts to zero, and quoted lowpriority extracts false so a higher-priority request plays. They assert active record identity, one-time stopping, stored priority and actual controlled-media play calls (`outputs/sound-priority-consumers-browser.log`). Full native capacity and audible-output behavior remain outside this evidence.

The pre-capacity full battle regression passed (`outputs/sound-ownership-full-browser.log`). A subsequent capacity implementation defaults to 32 slots per player pool, matching pinned `src/resources/defaultConfig.ini`; normal Helpers share their player's pool. Requests outside the configured logical range become automatic. Full pools reject low-priority requests, protect higher-priority clips and prefer eligible automatic sounds before numbered sounds for eviction. Independent two-slot tests cover pool isolation, rejection, normalization and eviction, and the existing actual actor suite passes (`outputs/sound-capacity-actor-browser.log`). Native tick timestamp/physical-slot tie-breaking and configuration UI/import parity remain pending; insertion order currently approximates oldest selection and is not certified native timing fidelity. Final combined regression must be rerun after this change.

Subsequent slot-order correction replaces the insertion-order approximation: records now carry a physical pool slot and signed simulation timestamp. Same-channel replacement retains its slot; free allocation chooses the first available slot; eviction orders eligible clips by oldest timestamp, then lowest slot, retaining automatic-channel preference. Tests explicitly reuse a freed lower slot at the same timestamp and distinguish timestamp age from slot order. Focused checks and actual actor regression pass (`outputs/sound-slot-order-browser.log`). Exact native `sys.gameTime()` parity across pause/round lifetime, configurable capacity import and actual saturation consumers remain unverified. Earlier insertion-order statements describe the superseded implementation, not current behavior.

Actual saturation consumers now pass for both player directions with two-slot test pools: a normally spawned Helper fills its root player's pool, the opposing player's clip occupies a separate pool, a lowpriority request is rejected, and an eligible automatic Helper clip is evicted without stopping either the higher-priority numbered clip or the opponent (`outputs/sound-capacity-consumers-browser.log`). This closes the basic actual pool-sharing/eviction gap, not pause-clock or complete capacity-configuration fidelity.

Still pending: remaining PlaySnd parameters (including volume, frequency, looping and stop flags), real SndPan output, complete native prefix/resource grammar, channel limits/capacity priority behavior, native lifetime behavior, further actual Helper media/scheduling consumers, final combined regression and verified publication. Neither PlaySnd nor StopSnd is certified complete. No whole-controller certification changes.
