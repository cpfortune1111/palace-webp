# VarRandom — partial consumer fidelity

Pinned reference: Ikemen GO cb56d73badb322f3725257c2e8cfd157b2c3989d, src/bytecode.go varRandom.Run and src/compiler_functions.go varRandom. Run evaluates redirectid, variable index and range, then calls varSet(v, RandI(min,max)); Go evaluates the random argument even when varSet will reject the variable index.

The WEB shared variable consumer previously skipped random generation on rejected indices, changing later random results. It now samples before checking the write bounds. Executable tests verify negative/out-of-range indices each consume one sample after index/range expressions, perform no write and preserve missing-redirect short circuit. Existing variable tests pass independently.

Sixteen actual browser cases now exercise both profiles, player slots, roots and normally spawned Helpers with negative/out-of-range indices. Each rejected write consumes the first fixed sample and the following valid controller observes the second sample, proving the real dispatcher reaches the changed consumer (outputs/variable-random-consumer.log). The production import cache version is bumped so deployed clients receive the changed module.

The pinned src/common.go Random/Rand/RandI implementation is now translated into a typed generator and range mapper. Independent BigInt checks cover signed seed recurrence, reversed/equal ranges, signed-width overflow and full int32 ranges. The production VarRandom dispatcher consumes this generator rather than a floating uniform approximation. Sixteen actual rejected-index cases and 24 real signed/reversed/equal/full-range consumers pass with explicit seed=1 and known native outputs (outputs/variable-random-native-consumer.log).

The first full-range browser expectation used the minimum int32 literal directly; the current expression parser yields a different boundary value for that spelling. The corrected mapping fixture constructs the minimum with (-2147483647-1), isolating RandI mapping rather than silently claiming compiler-boundary equivalence. Literal/compiler parity remains Pending.

GameMakeAnim now consumes float32 RandF from the same native stream as VarRandom. The 32 actual animation matrix cases use known integer samples and independently calculated float32 offsets rather than replacing Math.random. Four actual profile/player interleavings verify VarRandom -> three zero-width animation components -> VarRandom consumes exactly native samples 1 through 5; equal-width random operands still advance the stream. Float endpoint/reversal/equal-range checks pass independently (outputs/native-random-game-animation.log and outputs/native-random-shared-consumer.log).

AssertCommand empty-name selection and TargetDrop keepone selection now consume this same native integer stream, matching pinned char.go assertCommand/targetDrop calls to Rand. Eight actual profile/player/one-or-two-normal-Helper target fixtures verify selected command buffers, retained target IDs and the next VarRandom sample. One remaining target still consumes the native sample; omitted random selection does not use a substituted floating draw (outputs/native-random-selection-consumers.log).

Pinned bytecode.go OC_random calls Rand(0,999) on every evaluation. Both the fast query route and actual fighter/Helper expression contexts now sample the shared stream per occurrence instead of returning tick-cached randomValue. Eight actual profile/player/root-or-Helper cases verify repeated queries in one context, controller interleaving and AST repeated operands; context construction itself consumes no sample. The fast route has an additional live check (outputs/native-random-query-consumers.log). Legacy diagnostic randomValue fields remain but no longer implement the Random trigger.

RandomRange is now a real typed integer intrinsic, using the pinned two-argument compiler contract and bytecode.go random behavior. Both bounds evaluate in caller scope before undefined propagation; undefined operands prevent RNG sampling. Numeric bounds truncate to int32 before native RandI mapping. It is never classified as a constant expression. Independent checks and eight actual root/Helper/profile/player cases cover fractional/reversed bounds, shared sequence, left-to-right assignments, undefined RHS evaluation and lazy Cond exclusion (outputs/native-random-range-consumers.log). There is no added rounding-option parameter. String operands, complete literal/compiler/version diagnostics and foreign-expression ownership remain unproven.
