# Sprite layer passes (incomplete)

Nonzero priority now activates final composition even when body layer stays zero and there are no reflections/palette/transparency/under flags. Previously that scene could bypass the queue despite a real SprPriority value write. An actual presentation fixture temporarily isolates those activation conditions, verifies priority zero leaves the legacy path hidden and priority five enables the final output, then restores all state. This verifies the consumer selection boundary; default equal-priority legacy bypass and complete native overlay/performance equivalence remain Pending.

SprPriority nonzero layers now have a real controller-to-draw consumer, superseding earlier rejection notes. The controller samples present layerno before value, stages both operands before writing either field, commits priority then layer, and defaults omitted fields to zero without evaluating synthetic operands. Actual redirected controller cases write P1/P2/Helper live layer/priority bindings at layers -1/0/1/2 and verify all body records across four draws. Existing final compositor pixel cases verify exact pass inclusion, foreground occlusion and exclusion of unsupported layer numbers from drawing. Native bytecode accepts arbitrary int32 layers; unlike Explod layerno this is not sign-clamped.

Pinned reflection review corrected a potential wrong prerequisite: system.go chooses reflection passes from stage.reflection.layerno, independently of character c.layerNo, and explicitly notes that shadows do not yet follow source layers. Char.cueDraw still queues its shadow/reflection from body data. WEB root reflections are therefore not reassigned merely because SprPriority changes the body layer. Full stage reflection-pass selection, shadows/HUD/EnvColor/native synchronization/version/lifecycle equivalence remains Pending. This is tested partial behavior, not whole SprPriority certification or a claim that every visual phase is finished.

Synchronization ordering now has live Explod metadata consumers. synclayer and syncid use integer extraction; syncid=-1 resolves to the creating root or Helper instance identity. Actual Root/Helper browser cases verify these values reach draw records. Exact-layer queue sorting forms groups from the first positive syncId in the filtered pass, orders different groups newest-first, orders equal-priority members by syncLayer, and uses reverse insertion order for remaining ties. Focused tests cover interleaved groups, priority overriding group order, equal syncLayer ties and repeated queries. This follows pinned anim.go DrawList.draw and bytecode.go Explod sync handling. Native enableSyncId body registration, syncparams transform synchronization, all resource branches and full compiler evaluation order remain Pending; these parameters are not certified beyond the tested ordinary-effect paths.

Exact-pass sorting correction: pinned anim.go DrawList.draw filters layer first, then sorts ascending priority, with newer unsynchronized sprites first at equal priority. ONTOP is not a separate sort key after layer selection; an explicit layerno can override its layer while retaining its flag. WEB exact-layer queue calls now use priority and descending insertion order, so ONTOP cannot incorrectly lift a layer-overridden effect above higher-priority sprites in the same pass. Legacy unfiltered queue inspection retains its previous sorting to avoid claiming native pass behavior outside the compositor. Focused tests cover an ONTOP layer -1 priority-zero effect before priority-five effects and reverse insertion ties. SyncId/syncGroup/syncLayer native grouping remains Pending.

Explod layer parameters now have live consumers: applyExplodLayers applies ONTOP, under and layerno in pinned compiler order. ONTOP true selects layer one and resets sprite priority to zero; false selects layer zero. Explicit layerno follows ONTOP and clamps its extracted integer sign to -1/0/1, while under reaches the actual draw record. The ordinary spawn body no longer evaluates the original ONTOP operand a second time. Node tests cover evaluation order, boolean tags, invalid operands, integer truncation/wrap and inheritance. Actual browser cases create effects from both roots and a Helper with ONTOP=1, under=1, layerno=-8 and priority=9, then verify storage and drawing retain layer -1, priority zero and both flags. Full cross-parameter compiler ordering (including accel versus these fields), resource failures, redirect ownership, ModifyExplod and remaining parameters are still Pending. These tests do not certify the whole controller.

Explod creation inheritance now has a real Root/Helper consumer: spawnSourceExplod snapshots the creator layer before dispatching the existing animation/resource branches and writes it onto each newly created effect. Existing evaluated ONTOP true selects layer one; explicit false selects zero rather than inheriting. Actual browser tests create nine ordinary-animation effects from P1, P2 and a live Helper, change all creator layers afterwards, and verify both retained effect storage and final draw records. Pinned char.go Explod.initFromChar copies c.layerNo; bytecode.go explod ONTOP overrides the layer. Explicit layerno expression evaluation/clamping/order, native ONTOP priority reset, uncommon resource-branch ONTOP extraction, ModifyExplod, under and complete remaining parameters are still Pending; this inheritance fix does not certify those features.

Afterimage priority correction: pinned char.go recAfterImg starts each retained priority at captured sprite priority minus two; recAndCue only lowers that stored priority when it would overlap the current character, then subtracts the draw-step index. The real root afterimage draw now preserves the capture offset and persistent downward clamp instead of recomputing every historical priority from the live root on every draw. Actual browser cases cover captured priorities 10/30 with live priority 20, then -10, then 50, proving historical ordering and no rebound after lowering. Native sampling order/framegap/version differences and depth contributions remain Pending; this is not whole AfterImage certification.

Afterimage historical layers now reach real drawing: stepAfterImages captures each root's layerNo alongside its pose; drawAfterImages submits that stored layer instead of defaulting every historical sprite to zero. Pinned char.go AfterImage.recAfterImg copies the original SpriteData, including layerno, before queuing retained snapshots. The actual browser test captures opposite P1/P2 layers twice, changes both live roots to zero, then verifies all four recorded afterimages still use their individual historical layers. This fixes layer inheritance only; native ring sampling, priority adjustment, full palette snapshots and Helper afterimages remain Pending.

Actual actor draw evidence: drawTransSprite now reads independent rootSpriteLayers for root1/root2, and drawSourceExplods forwards Helper layerNo into the recorded layer rather than dropping it. Generic Helper controller bindings expose layerNo to the same live entity.
