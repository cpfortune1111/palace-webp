# Explod syncparams consumers (partial, unpublished)

Supplemental extraction checks assert compiler-relative ordering synclayer, syncparams, syncid, ONTOP, under, layerno; native-style true/false extraction rejects runtime numeric strings, NaN and undefined. Missing synchronization targets skip every copy/registration callback. This only proves ordering within this extracted subset; the surrounding Explod compiler order is still incomplete.

Synchronized color output now has pixel evidence beyond metadata. The actual Root/Helper draw records from synchronization tests are passed through the real renderOpaqueTransQueue and paletteShaderForDraw using a controlled opaque 60/30/90 source over 100/100/100. Independent expected RGBA assertions are 61/40/70/255 for add alpha 128/64 with PalFX +12 red, 16/70/10/255 for subtract with +24 red, and 83/40/70/255 when the retained root palette pointer changes to +55 after synchronization is disabled. The fixture normalizes source geometry to one pixel while retaining actual produced Trans/alpha/PalFX, so this verifies color composition rather than whole scene geometry or native GPU equivalence.

Destroyed-Helper end-to-end evidence now exists. A failing actual-browser test exposed one remaining body record after destroyed=true: synchronization registration was correctly pruned, but drawSourceExplods filtered invisible entities without filtering destroyed entities. The real draw collection now excludes both. The unchanged test verifies prior registration, zero destroyed body records, zero registration on an ID probe, and retained last synchronized values on the surviving Explod. Before-fix evidence is outputs/explod-destroyed-helper-before.log. This covers immediate destruction/rendering cleanup, not all native cross-round/replacement/simulation-phase behavior.

Actual character-preparation coverage now passes: the browser registers both root IDs, queues real draw records, calls the game's asynchronous prepareCharacters with the current selections, then verifies current records and subsequent draws both have cleared registrations. This tests the actual preparation hook rather than only queue reset methods. Destroyed-Helper end-to-end cleanup and broader round/replacement equivalence remain Pending.

Registration lifetime correction: pinned Char.init replaces the full native character struct, so enableSyncId starts false for a newly prepared character, whereas clearState does not explicitly reset that field. WEB prepareCharacters now clears body synchronization registrations on successful character preparation, including already queued body metadata, without changing ordinary per-frame resets. Before drawing effects, registrations for absent/destroyed Helpers are pruned; live root registrations remain and the runtime's monotonically increasing Helper instance IDs are preserved. Node tests cover selective removal, retained live IDs, clearing current records and an unregistered reused ID after reset. Actual character-preparation and destroyed-Helper browser coverage is required before claiming complete lifecycle equivalence.

Character synchronization registration now has a real queue consumer. Resolving a valid positive syncId registers the target body even with syncparams=false, matching native enableSyncId outside the parameter-copy conditional. Root and Helper draw records carry actor identities; registration updates an already queued body in the same frame and future records use syncLayer zero. Frame resets retain registration, including after an effect disappears. Actual browser coverage draws both roots and a Helper, verifies all three body sync identities/layers, removes the effects and checks the next draw. Node checks cover already queued and subsequently recorded bodies and unchanged unrelated actors. Character replacement/round/reused-ID lifetime equivalence still requires further review; this does not certify full synchronization lifecycle.

Scale/rotation consumers now use target size xscale/yscale multiplied by AngleDraw scale with float32 storage, while rotation copies only active AngleDraw angles. The actor pivot is deliberately not inherited: native sync copies rot but not an AngleDraw pivot. Effect scale and angle data are independent snapshots; the draw routine applies them to ordinary effects instead of restricting transforms to Helper entities, with unit angle scale to avoid double scaling. Actual Helper browser coverage verifies a 2x3 size with 1.5x0.5 AngleDraw produces a 3x1.5 scale and a 90-degree draw matrix, ignores actor pivot 8,9 and retains the copied transform after syncparams=false. Native perspective/window/shear/depth/local-coordinate interactions and complete rotation/final pixel equivalence still need verification; full syncparams remains Pending.

Trans/alpha and PalFX now also reach live effect drawing. Positive valid character synchronization copies Trans type/alpha values, but retains the target PalFX runtime reference, matching native value fields versus getPalfx pointer semantics. The draw queue samples that retained runtime, including after syncparams is disabled; copied alpha remains independent of later target array mutation. Ordinary effect Trans and PalFX now activate final composition and are used by drawSourceExplods rather than being restricted to Helper entities. Actual Root/Helper cases verify add/sub modes, both alpha values, palette additions, independent alpha retention and palette changes through the retained reference after disabling synchronization. Native scale/rotation/window/shear/projection/shader/afterimage copying and full final pixel/phase equivalence remain Pending.
