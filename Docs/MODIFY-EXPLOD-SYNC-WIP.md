# ModifyExplod synchronization consumers — partial, not full syncparams certification

Native defaults are syncId=-1, syncLayer=0 and syncParams=true. syncid=-1 resolves to the redirected recipient, not the caller.

Real synclayer/syncparams/syncid writes now reach selected effects. Signed layer offsets are not clamped; zero/nonpositive IDs disable target lookup, and missing targets retain prior copied values. syncparams=false still registers sync grouping but does not overwrite effect fields. The current visual consumer copies priority/base facing, size/AngleDraw scale and orthographic angles, window, shear, Trans/alpha and the shared PalFX reference. Alpha arrays are snapshots, whereas the retained PalFX reference remains live after synchronization is disabled. These are actual drawing/compositing consumers, not stored-only flags.

Modified synchronization opts into the existing staged native-effect lifecycle and is evaluated during the late update, including while parent hitpause freezes effect clocks. It is not re-evaluated by drawing. Unmodified legacy creation-sync effects retain their existing draw-time path to avoid unrelated behavior changes. Facing changes rotate the stored world-space velocity/acceleration back to the native local-velocity convention without changing already queued release displacement or fixed binding offsets. Sync updates precede eligible motion/animation stepping; disabled roots and expired effects retain the existing staged lifecycle gates.

Review found P1's character adapter did not expose the actual sprite priority, unlike P2 and Helpers. It now exposes reaction sprite priority or the normal P1 sprite-priority value, enabling both player directions rather than silently copying undefined.
