# MoveHitReset controller consumer (partial, unpublished)

Pinned reference: Ikemen GO cb56d73badb322f3725257c2e8cfd157b2c3989d, bytecode.go moveHitReset.Run/getRedirectedChar and char.go Char.clearMoveHit. Native clearMoveHit resets mctime and counterHit only. It does not call clearHitCount or clear MoveHitVar/contact metadata.

WEB MoveHitReset previously fell through to unsupported controller dispatch (outputs/move-hit-reset-before.log). A shared consumer now resolves optional redirectid with native signed integer extraction and clears only the selected Character. The adapter clears normal moveContact/moveHit/moveGuarded clocks, the reversal/contact override clock and countered flags. P1's live reaction record is updated alongside its ordinary root storage. Unknown payload fields fail explicitly; common hitpause/persistence metadata remains delegated to shared scheduling.

A zero-time contact clock is retained or created so expression contexts created before reset cannot return stale root snapshot fields. Existing clock type is preserved; a newly created internal clock uses hit type with zero time, which does not expose a positive contact query. Source hit count, active attack/contact metadata and MoveHitVar records are not reset.

check-move-hit-reset.mjs verifies omitted/redirected selection, signed ID wrapping, string/undefined/NaN extraction, missing-recipient early return, clock reset and preservation of count/metadata in the independent consumer fixture. Actual normal-spawn Helper/root/reaction-root fixtures cover hit, guard, reversal and absent override clocks in both profiles/player directions. Forty cases verify raw storage plus fresh and stale query contexts return zero, unrelated roots retain their contact values, nonzero hit counts remain and seeded MoveHitVar data is preserved (outputs/move-hit-reset-live-stale-browser.log). The initial thirty-case actual fixture also passes (outputs/move-hit-reset-consumers-browser.log).

Forty additional actual scheduling groups now cover omitted recipients in root current/global/lifecycle and normally spawned Helper current/global paths, CNS hitpause literal gates, persistent zero once-only current controllers versus repeatable global controllers, and blocked global pause versus positive Helper move-time allowance (outputs/move-hit-reset-scheduling-browser.log). Each idempotent reset is preceded by a nonzero seeded clock/counter state so a no-op or skipped controller cannot satisfy the positive cases. The normal Helper persistence cases run actual source-state steps rather than only manual controller calls.

Complete native diagnostics/compiler/version semantics, additional lifecycle/transition interactions and final regression/publication remain Pending. No whole-controller certification changes.
