# ModifyExplod visual consumers — partial

Pinned reference: Ikemen GO cb56d73badb322f3725257c2e8cfd157b2c3989d, bytecode.go modifyExplod facing/vfacing/sprpriority/layerno/ontop/under cases and MUGEN postype reset.

Facing and vertical facing respect native parameter locks and character-version restrictions: MUGEN characters cannot flip an already left-facing or upside-down effect back through these writes, while Ikemen characters can. Native postype reset uses the pre-commit facing state. Ontop=true forces layer 1/priority 0; ontop=false resets layer only when previously true. Under=true is sticky in the pinned implementation; false evaluates but does not clear it. Subsequent compiler/append/run review corrected the earlier inferred order: sprpriority, ontop, under, layerno. An explicit layerno is applied last and can override the ontop-selected layer. Earlier release logs asserting the reverse order are historical, not current native fidelity evidence; see MODIFY-EXPLOD-GEOMETRY-WIP.md.

Independent tests verify extraction order and these native conditional writes. Sixteen actual root/normal-Helper/profile/player/character-version cases verify effect fields, real drawing transforms and layer/priority/ontop/under draw entries (outputs/modify-explod-visual-consumers.log).
