# RemapPal — indexed-source groundwork, not implemented

Reference: Ikemen GO cb56d73badb322f3725257c2e8cfd157b2c3989d, compiler_functions.go remapPal, bytecode.go remapPal.Run and char.go remapPal.

The current atlas exporter expands indexed SFF sprites into RGBA and discards the index plane. Color matching on those expanded images would be incorrect: distinct indices can have identical source colors but different destination colors. RemapPal therefore requires retained source indices, palette metadata and a real actor/Helper-aware rendering consumer; storing a remap table alone is not implementation.

Tools/sff_indexed_palette.py now reads direct SFF v2 PNG8/LZ5 source indices and palettes without modifying the existing exporter or copying original SFF files. It preserves logical palette aliases separately from linked color storage and applies the same legacy alpha rule as the established exporter. Linked sprite decoding, other SFF versions/formats and malformed-source parity remain Pending. Python fixture tests pass for duplicate colors, distinct indices, palette links, axes, legacy alpha and bounds.

Engine/indexed-palette-pixels.js maps indices to exact destination RGBA with alpha. Its independent check demonstrates a duplicate-RGB source cannot substitute for index preservation. This is not yet connected to atlas assets, character palette state or drawing. RemapPal is not counted as implemented; complete controller extraction, native remap/default/duplicate/ownpal semantics and renderer/regression/publication remain required.

The indexed reader now implements this with cached shared index bytes, retaining each logical sprite's metadata. Invalid forward links are rejected rather than reproducing the native invalid-link fallback; preload-specific native palette-copy differences and malformed cases remain Pending. The existing RGBA exporter remains untouched while indexed atlas integration is developed.
