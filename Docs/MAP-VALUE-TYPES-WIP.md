## CNS constant compilation boundary (later correction)

Further source review of compiler_functions.go mapSetSub and compiler.go typedExp establishes an important distinction: map controllers request VT_Float for value. A folded numeric constant is converted to float32 before bytecode emission, whereas a dynamic expression retains its runtime tag because its compile result is VT_None. String literals emit runtime OC_string and are not converted as numeric constants. Literal Map := assignment is a separate compiler path and keeps its RHS tag.

Actual controller sampling now marks supported numeric constant expressions and applies that float conversion before storing/adding. Literal 3 therefore reads as float 3 and divides to 1.5; dynamic Var(0)=3 remains int and divides to 1. Constant undefined numeric results convert to float zero, while a dynamic division-by-zero value retains the undefined marker. Existing earlier int-wrap fixtures now explicitly use dynamic integer operands; their wrap assertions are retained rather than attributing that behavior to literal CNS values. This corrects the earlier insufficient producer-only interpretation.
