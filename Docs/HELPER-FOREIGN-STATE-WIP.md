# Helper foreign state programs — 0.25.39 partial implementation

Pinned reference: Ikemen GO cb56d73badb322f3725257c2e8cfd157b2c3989d, char.go stateChange1/stateChange2, targetState and hitResultCheck; foreign program identity is distinct from recipient ownership.

The Helper state-table lookup now resolves an explicit selected program provider instead of always selecting the recipient's own table. TargetState and P1StateNo source selections retain that provider through the real pending-header buffer, including when the caller returns to its own program before initialization. The existing physical/animation consumers remain owned by the Helper recipient; selected foreign StateDef expressions use the Helper's live context and shared own-root power. TargetState chaining from a Helper reads its actual provider rather than its root's provider.

Helper SelfState no longer clears its root's custom-state owner. It clears the Helper's own provider and enters the recipient's own program. The previous generic SelfState path both mutated the root and attempted to look up the own state in the foreign table.

Own negative/global controllers now explicitly use own-program metadata in their expression context even while the Helper's selected current program is foreign. A live -2 HitDef fixture previously mislabeled its snapshot with the foreign provider; it now records the Helper's own character and a false foreign-program flag. The fixture is exercised in all four source/target/recipient cases during actual hitpause. Red/green logs: controller-helper-foreign-global-before.log and controller-helper-foreign-global-after.log. This fixes that metadata consumer; it does not certify every negative-state query or the full scheduler.
