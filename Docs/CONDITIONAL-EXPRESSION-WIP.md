# 0.25.46 — Native conditional evaluation and numeric tags (partial)

Checkpoint: all 191 Node tools and focused actual conditional/controller fixtures pass. The final combined browser/deployment gates are verified separately. Chronological unpublished-stage observations below are retained as evidence; no full VM/controller certification is asserted.

Pinned reference: Ikemen GO cb56d73badb322f3725257c2e8cfd157b2c3989d, compiler.go IfElse/Cond cases (1733 onward), bytecode.go OC_ifelse and redirect/run handlers. This is partial VM/controller-parameter evidence, not complete expression compatibility or controller certification.

IfElse compiles its condition, first branch and second branch in order before OC_ifelse selects an already evaluated result. Cond compiles conditional jumps and evaluates only the selected branch. The WEB previously used the same lazy implementation for both, losing side effects in the unselected IfElse branch. Their real consumers now differ and capture the condition before evaluating either branch.

Redirected IfElse uses the original caller scope after the native redirect-reset instruction. Cond runs a nested bytecode block from the redirected actor. Expression contexts now carry originalActor separately from expressionOwner: nested Cond can reset the actor origin for assignment operands without replacing the original script's coordinate owner. Redirect and Helper/Target contexts propagate this distinct origin. This is not a claim that every redirect/query phase is complete.

Numeric evaluation also retains the selected supported branch's int/float tag through enclosing arithmetic, instead of inferring a common branch type or falling back to JavaScript division. Supported dynamic conditional results therefore distinguish IfElse(1,5,7)/2 = 2, Cond(0,5.0,7)/2 = 3 and IfElse(0,5,7.0)/2 = 3.5. The typed evaluator carries actual operand tags for supported numeric subtrees; unsupported query/function type families and the full undefined/VM model remain Pending.

Tools/check-conditional-evaluation.mjs tests actual parser/evaluator branch effects/order, condition capture, redirected IfElse/Cond scope, assignments and selected numeric types. It was red for eager effects, then red for lost integer type before the numeric consumer was repaired (outputs/conditional-evaluation-before.log and outputs/conditional-evaluation-order-after.log). Tools/check-conditional-browser.cjs exercises real P1/P2 root and Helper contexts/controllers in four source/recipient cases: variable reads, both IfElse side effects, Cond recipient writes and three float-parameter arithmetic results all pass (outputs/conditional-controller-browser.log). No simulated context alone is used as proof of those actual controller paths.

Broader native boolean behavior, query/function numeric tags, full redirection/coordinate phases, undefined values, constant-folding/version/platform details and the remaining VM/controllers/parameters are still Pending. Complete Node/browser regression and publishing are separate gates; this checkpoint is not yet released.
